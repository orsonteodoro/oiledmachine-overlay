The dev-python/instructor ebuild has a USE flag to enable litellm.  By
default the litellm USE flag is not enabled, and also it is not installed on
the ebuild maintainer's machine.  The litellm ebuild does not exist on
the oiledmachine-overlay.

We are all good right?

However, a few curious people may have wanted to try the feature out or wanted
all the USE flags enabled and used the http://gpo.zugaina.org/ to possibly copy
and paste the ebuild and modified it a bit to use the PyPI wheel.  The PyPI
wheel and Docker image is compromised according to AI.  The GitHub tarball
is not compromised according to AI.

Based on review of the 1.107* ebuild on the third party overlay, it is using
the GitHub tarball.  The narrative hasn't been verified.  As a precaution, the
1.107* is banned in the secure-version-python eclass and consequently in
dev-python/instructor.

Recently LiteLLM had recently had a supply chain attack.  It has been
circulating on the social media.  The AI has shared that one version
is compromised and the other version referenced on the portage overlays
website is insecure.

Affected and insecure versions

1.107.0 - Supply chain attack, infostealer, RAT (Remote Access Trojan)
  only if using PyPI tarball or Docker image.
1.91.1 - Insecure version
  CVE-2026-93355 (High 7.6), WA, DoS, DT
  CVE-2026-84377 (Medium 6.5), SSRF, ID

DoS - Denial Of Service
DT - Data Tampering
ID - Information Disclosure
SSRF - Server Side Request Forgery
WA - Weak Authentication

Checking if you downloaded the compromised or insecure versions:

realpath /var/db/pkg/dev-python/litellm*

Remediation

For 1.107.0, it is recommended to rotate both financial and login
passwords, revoke tokens, and replace sensitive credentials, API keys,
on a different device and to do a clean format on the affected devices.
Boot from a clean rescue USB to extract the valuable assets from the
device.  When copying data to the drive, create new home profiles do
not copy entirely the home profile because there is a risk of running
into persistent malware again.  In supply chain attacks, it is often
for financial gain or AI credit theft.

For 1.91.1, it is recommended to bump to the latest release ASAP.

It is recommended to have a local copy of the secured release of the
litellm ebuild or disable the USE flag.  For the local copy, you need
to start new ebuild.  Do not copy and paste the 1.107.0 ebuild.
