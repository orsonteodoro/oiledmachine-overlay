A critical vulnerability has been discovered affecting users of virtual machines.
This vulnerability is a VM escape vulnerability that leads
to arbitrary code execution.

Because this overlay was originally a performance overlay and those people the
overlay maintainer know do not use VMs, the advisory is not a priority.  This
advisory is passed on for users that still use VMs.

Stakeholders that it may affect:

CI/CD maintainers
Cloud devs/owners that use VMs
Developers
Blue team cybersecurity with VM labs
Red team cybersecurity with VM labs
Security Operation Centers (SOCs)
Security conscious users that prefer the use of VMs
Users that use multiple operating systems with VMs

Researcher vulnerability name:  PwnEscape

Severity:  Critical

CVE-2026-99999 - EBR, VME, ACE, IV, DoS, DT, ID

ACE - Arbitrary Code Execution
DoS - Denial of Service
DT - Data Tampering
ID - Information Disclosure
EBR - Extended Blast Radius
IV - Insufficient Validation
VME - Virtual Machine Escape

Remediation:

Simply `emerge -a <kernel-flavor>` to a new point release as it should fix the
security bug no matter what kernel flavor you use.  To avoid boot issues, make
sure to always up the update the initramfs.  To update the initramfs, use
genkernel or dracut.  The host bare metal machine must be triaged or upgraded
to the latest kernel point release for that slot [aka major minor version].

Examples:

emaint sync -A
emerge -a1vO "=sys-kernel/ot-sources-7.3.9999"
emerge -avuDN ">=sys-kernel/gentoo-kernel-bin-6.18.57::gentoo"

It is recommended to use the latest point release to remediate multiple memory
corruption vulnerabilities (UAF, OOBW, HO, SO, DF) as well.  In the recent AI
boom, about every kernel point release remediates multiple memory corruption
vulnerabilities giving attackers entry point options for their initial attack.

DF - Double Free
OOBW - Out Of Bounds Write
HO - Heap Overflow
SO - Stack Overflow
UAF - Use After Free

Optional related updates:

For standard VMs, confidential VMs, bootloaders, kernels, updating the CPU
firmware, motherboard firmware, and bootloader may be necessary to ensure the
integrity of the system to mitigate kernel security bypass, hardware level
side channels, or hijack to attacker compromised kernels.  There are risks of
bricking or expensive repair for this kind of remediation.

sys-firmware/intel-microcode - Ebuild available for Intel CPU firmware updates
sys-kernel/linux-firwmare - Ebuild available for AMD CPU firmware updates
sys-boot/grub2 - Vulnerabilities reported for this bootloader in late 2025
sys-boot/u-boot - Vulnerabilities reported for this bootloader in 2026
UEFI firmware - See manufacturer's site for update
