A critical vulnerability has been discovered affecting users of virtual machines.
This vulnerability is a VM escape vulnerability that leads
to arbitrary code execution.

Because this overlay was originally a performance overlay and those people the
overlay maintainer know do not use VMs, the advisory is not a priority.  This
advisory is passed on for users that still use VMs.

Stakeholders that it may affect:

Red team cybersecurity with VM labs
Blue team cybersecurity with VM labs
Security Operation Centers (SOCs)
Developers
Security users that use VMs
Cloud devs/owners that use VMs
Users that use multiple operating systems
CI/CD

Researcher vulnerability name:  PwnEscape

Severity:  Critical

CVE-2026-99999 - EBR, VME, ACE, IV, DoS, DT, ID

ACE - Arbitrary Code Execution
DoS - Denial of Service
DT - Data Tampering
ID - Information Disclosure
EBR - Extended Blast Radius
IV - Insufficient Validation
VME - Virtual Machine Escape

Remediation:

Simply `emerge -a <kernel-flavor>` to a new point release should fix the security
bug no matter what kernel flavor you use.  To avoid boot issues, also update the
initramfs.  To update the initramfs, use genkernel or dracut.  The host bare
metal machine must be triaged or upgraded to the latest kernel point release
for that slot [aka major minor version].

Examples:

emaint sync -A
emerge -a1vO "=sys-kernel/ot-sources-7.3.9999"
emerge -avuDN ">=sys-kernel/gentoo-kernel-bin-6.18.57::gentoo"

It is recommended to use the latest point release remediate the memory
corruption vulnerabilities (UAF, OOBW, HO, SO, DF) as well.  About every kernel
point release recently remediates a memory corruption vulnerability.

DF - Double Free
OOBW - Out Of Bounds Write
HO - Heap Overflow
SO - Stack Overflow
UAF - Use After Free
