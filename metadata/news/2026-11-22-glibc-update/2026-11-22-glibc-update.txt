This overlay will be using glibc 2.44-r4 as the default.  It is the maintainers
job to stay on top of security so that the developer machine and repositories
are not compromised.

However, you may opt out.  To opt out on the eager bump, add GLIBC_PV="2.43" to
/etc/portage/make.conf.  It is equivalent to RDEPEND=">=sys-libs/glibc-2.43".
The overlay sets it GLIBC_PV="2.44" but can be overwritten by the admin.

When the patch set was reviewed, it was viewed as incomplete.  This is why the
bump was eager ahead of stable KEYWORDS.  There is some suspicion as to why the
2.44 hasn't been been marked stable in 1 month for a critically-secure package.
It could be interpreted in a bad light as to leave several possible
vulnerability like bugs as unpatched.  One that overly takes security way too
seriously may assume that the system is already compromised and worthy of a
clean install.  For the Feds, they typically triage systems within 14 or 3 days
in comparison.

If you want to use 2.44, it is recommended to use the 2.44-r4 and to stay away
from the implied unfinished 2.44-r5.

Steps to update

Add to /etc/portage/package.accept_keywords/glibc:
=sys-libs/glibc-2.44-r4 ~amd64 **

# Sample full update.  Modify for your needs.
# gcc:15 for LTS packages (c++17 or earlier, e.g. most packages)
# gcc:16 for rolling packages (c++20 or later, e.g. hyprland)
emerge -vO linux-headers binutils-libs binutils gcc:15 gcc:16 glibc
# view compilers with eselect gcc list
# set compiler with eselect gcc set <number>
# view linker with eselect binutils list
# set linker with eselect binutils <number>
etc-update
source /etc/profile
emerge -pve @system # Fix all package manager issues first
emerge -ave @system
emerge -pve @world # Fix all package manager issues first
emerge -ave @world
