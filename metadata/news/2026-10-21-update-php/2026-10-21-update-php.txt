There are some reports on social media that the current fix is unpatched.  It is
advised to put the critical-secure HTTP servers offline until the situation has
settled and finalized.

Two critical severity vulnerabilities have been patched upstream by the PHP team.
It was estimated both would be 10s on the socials but downgraded to 9.2 for
CVSS 4, or 9.8 for CVSS 3.

Along with the 2 CVEs, the social media has shown a new 3rd CVE.  AI has
agreed about the remediation.

The release notes in the last two days hint of possible partial mitigation for
the previous 2 CVEs:
"There are no complete mitigations, updating is the only safe choice."

Researcher vulnerability name:  PHP2Shell

CVE-2026-109618 - RCE, UAF, UPTR, UBMA, IEH, ZC, DoS, DT, ID
CVE-2026-109619 - RCE, UAF, UPTR, UBMA, IEH, ZC, DoS, DT, ID
CVE-2026-115560 - (NEW) Reserved

DoS - Denial of Service
DT - Data Tampering
ID - Information Disclosure
IEH - Improper Exception Handling
RCE - Remote Code Execution
UAF - Use After Free
UBMA - Unbounded Memory Allocation
UPTR - Use of Uninitalized Pointer
ZC - Zero Click Vulnerability (AV:N, PR:N, UI:N)

Versions with the fixes:

PHP 8.5.12
PHP 8.4.27
PHP 8.3.36
PHP 8.2.35

To update, pick one of the following:
emerge -avuDN dev-lang/php:8.5::oiledmachine-overlay
emerge -avuDN dev-lang/php:8.4::oiledmachine-overlay
emerge -avuDN dev-lang/php:8.3::oiledmachine-overlay
emerge -avuDN dev-lang/php:8.2::oiledmachine-overlay

Mitigation for the new CVE-2026-115560 currently requires manual configuration in
php.ini:

session.upload_progress.enabled = 0

This setting is verified in
https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp

This setting only need to be applied for non default configurations or
configurations that use a non default setup where session.serialize_handler
is set to php_binary or php_serialize then switched to php via ini_set()
before session_start().

If you are using a local build that is outdated, it was suggested by other
security reports to put the server offline (or disconnect it from the network)
until the remediation to the newer version is complete.

It is preferred to disable the HTTP server, remediate, then put it back HTTP
server online.  The alternative is to disable the PHP module temporarily
with under maintenance message.

While the technical/definitional blast radius is limited, your personal threat
model or circumstance may treat it or interpret it correctly as extended.
