Note this report uses AI.

There was a recent of disclosure of 6 kernel vulnerabilities marked
with the ZDI prefix on the Linux Kernel Mailing List (LKML)
breaking the industry responsible disclosure guidelines.

ZDI-CAN-34068 received pushback from a kernel maintainer.

At this time, virtually all kernels are unpatched.

For remediation, some of it has already been done.  For custom configs,
you may need to remediate manually.

For the ot-kernel home users are mostly not affected only datacenters,
enterprises, virtual machine users, NVME users, ConnMan users.


Vulnerability analysis with estimated severity:

ZDI-CAN-33774 - RCE, RC - Critical
ZDI-CAN-33549 - RCE, IU - Critical
ZDI-CAN-33367 - LPE, OOB, LF, PCW/PCC - High
ZDI-CAN-34068 - LPE, OOBW - High
ZDI-CAN-34076 - URES, ID - Medium
ZDI-CAN-32005 - LPE, SO - High

IU - Integer Underflow
LF - Logic Flaw
LPE - Local Privilege Escalation
OOB - Out of Bounds
OOBW - Out of Bounds Write
PCW - Page Cache Write Vulnerability (e.g. Dirty Pipe, Copy Fail)
PCC - Page Cache Corruption Vulnerability [synonym for PCW]
RC - Race Condition
RCE - Remote Code Execution
SO - Stack Overflow
URES - Use of Uninitalized Resource


sys-kernel/ot-kernel defaults:

CONFIG_SMB_SERVER - OFF or ON [1]
CONFIG_SMB_SERVER_SMBDIRECT - Default OFF
CONFIG_DRM_VMWGFX - OFF or ON [2]

[1] If net-fs/ksmbd-tools is not installed, it is OFF.  Otherwise, it
is ON if you are using config assist `OT_KERNEL_CONFIG_MODE="assist"` and
`OT_KERNEL_AUTO_CONFIGURE_KERNEL_FOR_PKGS=1`.

[2] If open-vm-tools or virtualbox is not installed, it is OFF.  Otherwise, it
is ON if you are using config assist `OT_KERNEL_CONFIG_MODE="assist"` and
`OT_KERNEL_AUTO_CONFIGURE_KERNEL_FOR_PKGS=1`.

Config assist with auto pkgflags allows to enable all the kernel config symbols
automatically based on packages installed.

Short term mitigations:

The first four can be mitigated by changing the kernel .config.

| Vulnerability ID | Mitigation                    | How much mitigation with this change? | Subsystem/Device                                  | Stakeholders affected                                                        |
|------------------|-------------------------------|---------------------------------------|---------------------------------------------------|------------------------------------------------------------------------------|
| ZDI-CAN-33774    | CONFIG_SMB_SERVER=n           | Full                                  | KSMBD (In kernel SMB file server)                 | Enterprise admins, server operators, R&D, academics, embedded/IoT developers |
| ZDI-CAN-33549    | CONFIG_SMB_SERVER_SMBDIRECT=n | Full                                  | RDMA/SMB Direct transport framework               | Enterprise admins, network architects, cloud providers, HPC                  | 
| ZDI-CAN-34068    | CONFIG_DRM_VMWGFX=n           | Full                                  | VMware Graphics Driver (vmwgfx)                   | VM admins, DevOps, cloud consumers                                           |
| ZDI-CAN-34076    | CONFIG_NVME_TARGET=n          | Full                                  | NVMe Target Core (nvmet)                          | Data center & storage admin/providers                                        |
| ZDI-CAN-33367    | [3]                           | Partial                               | Network skbuff Core (skb_zerocopy)                | Shared hosting, multi tenant environments, kernel devs                       |
| ZDI-CAN-32005    | DNS Proxying OFF              | Partial                               | Networking Stack, not kernel but with ConnMan v2  | Embedded/IoT, automotive linux, handheld linux gamers                        |

[3] Use `sysctl -w kernel.unprivileged_userns_clone=0` or `user.max_user_namespaces = 0`
for systems that run untrusted code locally.  Use the AI for help.

Document all changes so they can be reverted back after each has been fixed.

=n means it is unset, comment out, or remove in the .config file.

For ot-kernel or any kernel flavor, you can either modify the kernel config
in for example `/etc/kernels/kernel-config-<arch>-<version>-gentoo` for
newer kernel packages.

  or

in `/usr/src/linux/.config` per file directly in the old school way of building
the kernel.

  or

(ot-sources only) use the following in your per kernel
`/etc/portage/ot-sources/<BRANCH>/<EXTRAVERSION-FLAVOR>/<ARCH>/env` file
when using OT_KERNEL_CONFIG_MODE="assist"

  OT_KERNEL_KCONFIG[CONFIG_SMB_SERVER]=n
  OT_KERNEL_KCONFIG[CONFIG_SMB_SERVER_SMBDIRECT]=n
  OT_KERNEL_KCONFIG[CONFIG_DRM_VMWGFX]=n
  OT_KERNEL_KCONFIG[CONFIG_NVME_TARGET]=n

This is preferred for ot-sources because this is designed as the final
config override.  In ot-sources with assist mode, the .config are the
fallback default, then the config assist overwrites, then the final
OT_KERNEL_KCONFIG settings overwrite.

  or

(ot-sources only) For OT_KERNEL_CONFIG_MODE="custom", you can use the .config file in
/etc/kernels/kernel-config-<KV>-<FLAVOR-NAME>-<ARCH> or the one
associated with OT_KERNEL_CONFIG="/etc/kernels/kernel-config-<KV>-<FLAVOR_NAME>-<ARCH>"
in `/etc/portage/ot-sources/<KV_MAJOR_MINOR>/<FLAVOR_NAME>/<ARCH>/env`

TIP:  If using menuconfig, you can use / to do a symbol search.  For example search
for SMB_SERVER and then press 1 for the first search result.
